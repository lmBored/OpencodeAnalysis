\begin{itemize}
        \item \textbf{Maintainability, Modularity (evidence: strong).}
        The root \href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/package.json#L25-L32}{\path{package.json} (L25--32)} declares Bun workspaces, so every package has its own \path{package.json} and declared dependencies. 
        The dependency direction is an explicit rule in \href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/AGENTS.md#L3}{\path{AGENTS.md} (L3)}: \emph{``Keep runtime dependencies directed from Schema to Core and Protocol, then from Core and Protocol to Server. Client runtime code may depend on Schema and Protocol but never Core or Server''}.

        \item \textbf{Maintainability, Testability (evidence: strong).}
        Every package has a \path{test/} directory mirroring \path{src/}. For example, \path{packages/core/test/} has 88 entries against 83 in \path{packages/core/src/}, including \path{permission.test.ts} for \path{permission.ts} and \path{credential.test.ts} for \path{credential.ts}. 
        Tests run on every push to \texttt{dev} and on every PR in \href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/.github/workflows/test.yml#L66-L80}{\path{.github/workflows/test.yml} (L66--80)}: unit tests via \texttt{bun turbo test}, a generated client check, and HttpApi ``exerciser gates'', on both Linux and Windows. 
        Playwright end-to-end tests follow at L136--137, and \path{typecheck.yml} runs \texttt{bun typecheck}. 
        One inconvenience and unconventional practice is that tests cannot run from the repository root (\href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/AGENTS.md#L141-L145}{\path{AGENTS.md} L141--145}); they have to be run per package. 

        \item \textbf{Security, Confidentiality (evidence: weak).}
        Provider credentials are stored in the local SQLite database. 
        The table in \href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/packages/core/src/credential/sql.ts#L5-L14}{\path{packages/core/src/credential/sql.ts} (L5--14)} defines the secret as a plain JSON text column (\texttt{value: text(\{ mode: "json" \})}), and \href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/packages/core/src/credential.ts#L108-L116}{\path{credential.ts} (L108--116)} inserts \texttt{credential.value} as it is. 
        We also searched \path{packages/core}, \path{packages/opencode}, and \path{packages/server} for \texttt{encrypt}, \texttt{keychain}, \texttt{keytar}, or \texttt{safeStorage}, but found no encryption at rest and no OS keychain integration.
        \textbf{Outcome:} secrets are protected only by file system permissions, so we rate this evidence as weak. 
        
        \item \textbf{Security, Resistance (evidence: absent by design).}
        The project states explicitly that it provides no isolation: \emph{``OpenCode does \textbf{not} sandbox the agent. The permission system exists as a UX feature [\ldots] it is not designed to provide security isolation. If you need true isolation, run OpenCode inside a Docker container or VM''} (\href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/SECURITY.md#L15-L19}{\path{SECURITY.md} L15--19}), and it lists ``sandbox escapes'' as out of scope (L30). 
        The codebase also aligns with this: \href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/packages/core/src/permission.ts#L76-L86}{\path{packages/core/src/permission.ts} (L76--86)} only matches an action/resource pair against wildcard rules and falls back to \texttt{"ask"}, and an agent without rules gets a ruleset that \texttt{"deny"} everything (L15). 
        This default prompts the user, which is reasonable, but the check runs inside the same process as the shell tool, so it offers no protection against a compromised model or a malicious plugin.
        Moreover, plugins can even override decisions through the \texttt{"permission.ask"} hook (\href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/packages/plugin/src/index.ts#L261}{\path{packages/plugin/src/index.ts} L261}). 
        \textbf{Outcome:} we found no evidence of resistance against attacks, and it seems that the project hands this responsibility to the user.

        \item \textbf{Flexibility, Adaptability (evidence: strong).}
        Models and providers are not hard-coded (which is also one of the core selling points of OpenCode).
        \href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/packages/core/src/models-dev.ts#L67-L132}{\path{packages/core/src/models-dev.ts} (L67--132)} defines schemas for an external model catalog (models.dev), and \path{packages/core/src/provider.ts} only re-exports provider types (\texttt{AISDK}, \texttt{Native}, \texttt{Api}), so a new provider can be added as a catalog entry without changing the codebase.
        The public plugin API in \href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/packages/plugin/src/index.ts#L216-L334}{\path{packages/plugin/src/index.ts} (L216--334)} defines about twenty hooks, including \texttt{models}, \texttt{chat.params}, \texttt{chat.headers}, \texttt{tool.execute.before/after}, \texttt{shell.env} and \texttt{tool.definition}. This design lets users adapt model selection, requests, tools and the shell environment straight from UI and config files. However, we notice the \texttt{experimental.*} prefix on several hooks, which shows that parts of this API surface are not yet stable.

        \item \textbf{Flexibility, Installability (evidence: strong).}
        There are three main points that cover installability.
        First, \href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/install#L81-L165}{\path{install} script (L81--165)} detects the operating system (Darwin, Linux, MINGW/MSYS/Cygwin), the CPU architecture, the C library (musl vs.\ glibc) and AVX2 support, and chooses one of five target binaries (\texttt{linux-x64}, \texttt{linux-arm64}, \texttt{darwin-x64}, \texttt{darwin-arm64}, \texttt{windows-x64}) with \texttt{-baseline} and \texttt{-musl} variants. 
        Second, package manager installation is also covered: \href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/README.md#L50-L61}{\path{README.md} (L50--61)} lists \texttt{curl}, npm/bun/pnpm/yarn, Scoop, Chocolatey, Homebrew, AUR and Nix, and \href{https://github.com/anomalyco/opencode/blob/b471c2b4495747353af768fbf2e0790c9d820ce2/flake.nix#L11-L15}{\path{flake.nix} (L11--15)} builds for four Nix systems. 
        Third, releases are automated by \path{.github/workflows/publish.yml}, which reduces the risk of broken manual releases.
    \end{itemize}
